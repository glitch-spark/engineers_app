# App Reorganization — Steps 1–2 (Menu & Names, One Filter Bar) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Regroup the sidebar and rename routes (Plans, Account settings) with redirects and the step-1 fixes, then put every page's filters on one shared filter bar with one date-range control, one search box, one segmented control and one pagination.

**Architecture:** Frontend-first. A pure date-range module (`lib/dateRange.ts`, unit-tested with Vitest) defines presets, ranges, stepping, labels and URL encoding; shared components (`FilterBar`, `DateRangeFilter`, `SearchFilter`, `Segmented`, `Pagination`, `useUrlFilters`) sit on top; pages migrate one per task. Backend changes are small and isolated: links, an interview read-only summary, a phone field, an Interviews `q` search, and a 2-pay-week Bidders period.

**Tech Stack:** React 18 + Vite + SWR + TS + Tailwind (+ Vitest, dev-only, for `lib/` logic); FastAPI + Beanie, pytest + mongomock (`tests_unit/`).

**Spec:** `engineers_app/docs/superpowers/specs/2026-11-14-app-reorganization-design.md` (sections "Target structure", "Consistency → Names and routes", "One filter bar for every page", "Steps" 1–2).

## Global Constraints

- Sidebar order and groups (spec "Target structure"): `Dashboard` · `Plans` · group **RESUMES**: `Profiles`, `Generate`, `Job Applies`, `Prompt Eval` · `Bidders` · `Interviews` · `Transactions` · divider · `Statistics` · group **ADMIN** (admins only): `Users`. Group headings hidden when the sidebar is collapsed (as the Admin heading is today).
- Routes: Plans at `/plans` (`/report` and `/weekly-plan` redirect, **keeping the query string**); Account settings at `/account` (`/profile` redirects, keeping the query string); menu item and page title both "Account settings". "Generated resumes" spelled one way everywhere.
- Date presets, in this order: `This week · Last week · Last 2 weeks · Last month · This month · This year · Custom` (values `this_week, last_week, last_2_weeks, last_month, this_month, this_year, custom`). Interviews adds `Next week` (`next_week`) right after This week. AI usage adds `Today`, `Yesterday` (`today`, `yesterday`) below the standard list; profile statistics add `All time` (`all_time`) below it.
- Last 2 weeks = Monday two weeks ago → last Sunday. Last week = previous Mon–Sun. Last month = previous calendar month. This week/month/year = the whole calendar period; when `allowFuture` is false the end is clipped to today and › is disabled at the current period.
- Weeks are Monday–Sunday for all filters. Custom ranges: from ≤ to, at most 366 days; messages "Pick both dates." / "From must be on or before To." / "Pick a range of a year or less."
- ‹ › moves the range by its own length (week, 2 weeks, month, year, or the custom range's day count); a stepped range that matches no preset shows as Custom; the label always shows the actual dates (e.g. `Nov 9–15, 2026`, `Oct 26 – Nov 8, 2026`, `Nov 2026`, `2026`).
- Old Interviews URL values map on read: `prev_week` → `last_week`, `prev_month` → `last_month`.
- Bidders date presets: `This pay week · Last pay week · Last 2 pay weeks · This month · Last month · Custom` (values `this_pay_week, last_pay_week, last_2_pay_weeks, this_month, last_month, custom`); label shows the server's pay-week label for pay-week presets.
- Filter bar order: who (User/Owner) → page-specific → search → date range → `Clear` (shown only when something differs from the page default). Statistics' bar stays sticky; others are not.
- Search box: 🔍 icon, × clears, Esc clears, 300 ms debounce, URL key `q`; placeholders exactly: "Search profiles…", "Search companies…", "Search users…", "Search job descriptions…", "Search interviews…", "Search bidders…".
- URL keys: `range`, `from`, `to`, `q`, `page`, `size`, plus page-specific keys; defaults are left out of the URL.
- Pagination sizes `10 / 20 / 50 / 100`, default `20`, label "Per page"; Job Applies run table keeps `25 / 50 / 100 / 200`.
- Region list: `All · LATAM · EU · US · Canada · Asia · No region` (values `'' , Latam, EU, US, Canada, Asia, none`), each page showing the subset its endpoint supports (Statistics: All/LATAM/EU/US).
- Time zones and server period contracts don't change (except the two backend additions: Interviews `q` in Task 7 and Bidders `weeks=2` in Task 9).
- The Dashboard's CompareCard/TeamOverview period toggles are not migrated here: those cards move to Statistics → Team in step 3 and get the shared bar there.
